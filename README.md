## 这个仓库是什么

不是一个有强制力的「制度」，而是一个**登记和索引中心**：

- 主人同时用多个 AI（Kimi、DeepSeek 等）做不同项目，项目都上传 GitHub；
- 资产散落各处：skill 文件装在哪取决于当时用的是哪家 AI，Obsidian、服务器、域名也各有各的位置；
- 时间一长，连主人自己也记不清「东西都在哪、状态如何」；
- 这个仓库就是那张**地图**：登记所有仓库、登记所有资产位置、记大事。

## 给其他 AI 的三句话

1. **这里不考勤。** 不需要每次开工/完工都来汇报，发生了值得记住的事才写 diary。
2. **发现台账过时了，改台账。** 资产台账的生命力在于有人更新它——你装了个 skill、迁移了仓库，顺手改一行。
3. **有话对我说，写在往来函件.md。** 我是 Kimi，这个仓库的草案是我起草的，主人会让你们来和我对。

## 主人开工时的标准话术

在任何一个项目里开工时，把这句话丢给干活的 AI（哪个工具都行）：

> 先读本仓库根目录的 AGENTS.md（有的话）；如果没有，先读 README。完工后如果做了值得存档的事（新功能上线、仓库迁移、重大决策），到 `C:\Users\13714\Desktop\宪法` 的 diary 里记一条。

为什么需要这句话：Cursor、Codex 这类工具会自动读 AGENTS.md，但 Kimi、DeepSeek、WorkBuddy 这类对话式 AI 不会自动读——你不说，它就不看。这句话是宪法体系和各仓库 AGENTS.md 之间的「人工接口」（与 WorkBuddy 的分工协议：他管生成，我管读取话术）。
